# Core事件与通用TCP维护说明

2026-10-27。Core通用TCP与NetClient/PulletNet分别维护。本次没有合并两种连接体系，也没有改NetClient安装副本。

## 事件：固定派发集合，保留明确的变更语义

原实现直接遍历LinkedList节点；回调退订自身会截断遍历，回调清空待派发列表会让外层旧下标越界，异常则可能让延迟事件每帧重复执行。

现在每个事件类型缓存监听快照，仅注册集合变化时重建；同一次派发中的新增不参与当前调用，退订与清空对未执行监听立即生效。仍采用后注册先调用的原顺序。异常按监听隔离并记录，不将延迟事件自动重放。

下一帧待投递项先移交本帧批次，再进入用户回调。批次由Update持有，ClearAll/Destroy通过版本使剩余工作失效，不直接改动正在遍历的批次。等待队列一次压缩，避免逐条RemoveAt反复搬移；缓冲列表复用，未引入逐帧全量监听快照。

## TCP：一次连接持有一次IO生命周期

- 候选连接持有Socket与SocketAsyncEventArgs。关闭时退休该候选，物理完成负责释放仍在用的Args；已经排到主线程的旧结果不能再创建通道。
- Connect结果统一在主线程Update交付；重复Connect拒绝，用户回调异常隔离。网络失败允许显式重连，Dispose为不可逆终态。
- 发送保留当前批次与偏移，成功完成必须有正向字节进度，全部完成后才取新批次。同步完成与异步完成各结算一次。
- IO线程只提交完成记录，不直接调用业务处理器。Dispose立即关闭接纳与Socket，缓冲资源在物理完成后释放，不靠后续Unity Update。
- 接收或编解码失败关闭当前通道，避免“连接看似还在但不再接收”。错误回调绑定具体通道，不用一个旧通道的失败关闭新连接。
- 修正默认消息ID只读取16位的问题；默认发送帧字节格式未改。

公开调用、线程约束和兼容变化见[核心使用手册](../PulletFramework/README.md#core-通用-tcp)。尤其注意未连接发送不再静默丢弃，Send(id, object)仅接收已编码字节数组，Dispose后的客户端不可复用。
