# 事件与TCP修复说明

2026-10-27

## 事件派发

修复了回调退订自身时中断遍历、清空事件时列表越界，以及异常事件被下一帧重复执行的问题。

现在每种事件缓存一份监听快照，仅在注册集合变化后重建。监听仍以后注册先调用的顺序执行：新增监听从下一次Send起参与，退订和清空会跳过当前尚未执行的监听。单个回调异常记录后继续派发。

延迟事件先从等待队列移交到当前批次，再调用监听。ClearAll和Destroy使剩余批次失效；回调中新投递的事件至少等到下一帧。队列按批压缩，列表复用。

## Core通用TCP

Core TCP面向自定义帧协议，NetClient则连接PulletNet服务端，两者分别维护。

本次修复：

- 保留发送批次与偏移，部分发送完成后继续发送余下字节。
- 客户端持有连接中的Socket，Dispose关闭候选连接，迟到结果不再建立新通道。
- IO完成后释放仍在使用的缓冲区与EventArgs，关闭不依赖继续调用Update。
- 连接结果在主线程交付，重复Connect明确报错，业务回调异常单独记录。
- 编解码失败关闭通道，网络故障后允许显式重连。
- 默认消息ID完整读取32位，与发送格式一致。

### 调用变化

Dispose后需要新建客户端。未连接发送会报错；Send(id, object)接受已编码的byte[]或null，其他对象先自行编码。原方法会忽略传入的对象。

完整用法见[核心手册](../PulletFramework/README.md#core-通用-tcp)。Core TCP尚未提供TLS和发送队列预算，公开网络接入时需要考虑这些限制。
