## 状态标记

- **已确认**：已从当前代码、配置或编译结果核对。
- **用户验收**：由开发者工具或人工操作确认，但未形成自动化测试。
- **待验证**：已有实现，尚未完成目标平台端到端验收。
- **规划中**：尚未实现或还未决定最终方案。

## 模块状态

### PulletFramework

状态：**已确认**

- Window 支持导航栈、弹窗队列、Loading、Toast、返回键拦截、动画和安全区适配。
- `PulletResources` 只为框架内的 UI、Form、Sound 和 Pooling 提供资源策略，不替代业务资源系统。
- Pooling、UI 和 Sound 已补充异步句柄、释放、取消及包卸载前的生命周期处理。
- HTTP/HTTPS 与 WebSocket 保留通用调度层，并允许小游戏平台注入传输实现。
- `PulletPlayerPrefs` 默认使用 Unity 存储，平台模块可安装无反射的微信或抖音后端。
- `PLogger` 是 Pullet 模块唯一 Unity 日志出口。`PulletSettings.logLevel` 只控制运行时日志；编辑器构建、上传和配置错误始终输出。

### PulletFramework.YooAsset

状态：**已确认，平台缓存闭环待验证**

- YooAsset 采用独立可选模块，不侵入基础框架。
- `PulletYooAssets` 提供包级门面，支持默认包和多个按需 Package。
- `PulletYooAssetPackagePipeline` 负责文件系统初始化、版本请求、清单更新、可选下载和清理。
- 支持指定 Package 的检查、下载、暂停、恢复、取消、缓存清理、资源卸载和包销毁。
- 业务资源加载仍直接使用 YooAsset `ResourcePackage` API，避免重复封装资源加载接口。
- 编辑器提供 Package 构建、发布报告、供应商配置和腾讯云 COS 上传能力。
- 资源版本与 Player 版本分离；纯资源更新不要求修改 Player 版本。

## 关键架构决定

1. 基础框架、YooAsset、小游戏平台、资源发布和 HybridCLR 保持独立模块。
2. 游戏采用单一启动入口，资源包启动统一走 `PulletYooAssets`，不保留旧的双轨初始化 API。
3. 框架只抽象自身需要的资源能力；业务代码直接使用 YooAsset，避免再次包装其完整 API。
4. Player 版本和资源 Package 版本独立管理。资源版本可以使用日期版本或项目自定义递增版本。
5. 编辑器工具日志不受运行时日志等级影响。
6. 未明确要求时，不反复执行耗时的 PC 或 WebGL 平台构建。
