# U3/U4-A：多来源 Payload 派发内核

2026-10-16。接续 U2 `8815047`，本批只交付内部派发 owner 及其测试，不声称完成 Unity 多客户端入口。Native、wire、包内 DLL、旧 Manager、RPC/Messaging/Discovery 和正式消费者均不改。仍在 `codex/unity-single-connection` 本地分支，不推送、不发布、不再审计 Native。

## 本批职责与固定合同

`Runtime/ClientDispatchQueue.cs` 是未来 Unity 多客户端适配的唯一 Payload 队列，不是网络连接状态机、事件总线或第二层后台派发。旧 `PulletMainThreadEventPump` 暂由 U2 Manager 使用；后续门面迁移后退役旧队列，不把两套串起来。当前新增类均 internal，尚无公开多客户端入口或 SDK 断开联动。

### 来源与交付代际

- 注册准确的 SDK `HostedClient` 引用，不用 Key、SessionId 数字或另造全局 ClientId 判断归属。同名新客户端产生新来源句柄，旧句柄无法向替代来源入队；不同队列的来源被拒绝。
- `Source.Generation` 只管理 Unity 交付，不是 SDK 连接状态或协议 BindingEpoch。适配层未来必须在 SDK 的实际新 Session 边界调用 BeginSession，不能推迟到 Update；失效只清本来源。
- SDK 保留 Session 的显式重绑不等于新 Session，当前仍不向 Unity 暴露重绑入口；本类不推断 SDK 状态。
- 一个来源出现可靠交付故障后不允许靠 BeginSession 重开。必须交由适配层收口实际来源；本批只保留故障事实，不伪造已断开或已恢复。

### 预算和所有权

默认最多32来源；全局4096条/16MiB，每源1024条/4MiB；每帧最多256条/1MiB。构造时冻结正数配置快照。实际有效字节不是 ArrayPool 容量、对象元数据或进程 RSS；源码未承诺零分配。

先在同一锁内预留全局和每源数量/字节，再在锁外 ToOwned。预算包含准备复制、已排队和已出队但同步回调尚未退出的数据；Owned.Dispose 后才退预算。复制失败、关闭或旧代际迟到只由其唯一 reservation owner 结算；可靠复制失败保留首因，已入队可靠数据一并失效。清队列不强行归零准备中/消费中责任。

不可靠满载丢入站消息，不驱逐其他来源的数据；这是新多来源队列的明确策略，不照搬旧单源“替换旧非可靠”的策略。可靠满载进入该来源固定故障槽并关闭其交付接纳，其他来源继续处理；首因不能被后续拒收覆盖，不递归向满队列入故障 Action。

单条大于每帧字节额度的数据在复制前拒绝（可靠则来源故障），防止永远堵住 FIFO。队列暂不接收超过本层交付配置的大消息，不影响 SDK 的协议最大包长规则。

### 公平、回调与退出

每源 FIFO，跨源 round-robin，游标跨帧保留；同时受全帧条数和字节限制。某源头部暂不适合本帧剩余额度时保留它并检查其他源，下帧可重试。公平的是已接纳数据的交付机会，不保证每来源都能在全局预算已满时入队，也不抢占耗时的用户回调或承诺帧时长 SLO。

只允许单消费者 Drain，禁止并发/递归；本内核不绑定 UnityEngine，未来适配层负责仅在主线程调用。出队是回调进入的线性化点，关闭后仍须等待这些已进入责任退出。回调与诊断异常均不跳过后继来源和释放；本层只调用一个 delivery delegate，多订阅者隔离由未来事件适配层负责。

Retire关闭本来源交付，等待复制/回调中的 reservation 真正释放后才退来源名额；Close不可逆地退役所有来源，共享同一个关闭任务。可在交付回调中请求 Close，但不得同步等待依赖自身退出的任务。此完成只证明派发内存责任结算，不代替 SDK Host 的回调/物理IO/最终Dispose；将来适配层必须同时加入两者。当前没有添加后台任务、网络断开器或清理超时。
