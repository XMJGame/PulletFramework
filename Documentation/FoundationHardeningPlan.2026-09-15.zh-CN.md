# Pullet 基础加固修改计划

日期：2026-09-15。

依据：[基础审查](FoundationReview.2026-09-15.zh-CN.md)，以及随后关于 PulletResources、业务原生 YooAsset API、Pooling 归属和高频使用的讨论。

**状态：S0-S2、S4 已完成；S3 等待平台验收，S5 自动化测量已完成但真机 Profiler 待执行，S6 自动化部分已完成且平台验收待执行。本文按实际验证结果更新，不代表全部加固完成。**

## 一、固定架构边界

1. `PulletFramework` 不依赖 YooAsset、云厂商或小游戏 SDK。
2. `PulletResources` 保留为 UI、Form、Sound、Pooling 使用的最小资源适配层；不增加版本、下载、CDN、场景管理等完整资源系统功能。
3. `PulletFramework.YooAsset` 负责资源适配器与包级 Pipeline；业务自己管理的资源使用原生 ResourcePackage 和资源句柄，不重复封装官方加载 API。
4. `PulletPooling` 保留在核心框架。业务调用框架 Pooling 时，内部经过 PulletResources 是正常行为，不要求业务绕开框架服务。
5. 资源加载可以有两种入口，初始化、更新、卸载等包生命周期必须统一协调；适配器与业务共用同一底层资源包。
6. 谁取得资源句柄谁负责释放；池持有预制体依赖直到其实例销毁。包卸载由应用流程先协调使用者退出，再执行包级销毁，不让 YooAsset 模块反向依赖 UI、Sound 或游戏逻辑。
7. 通用发布服务管理供应商和上传协议；YooAsset 管理资源文件及发布顺序；小游戏模块管理平台首包。

不在本轮实施：搬迁 Pooling、增加第二套 YooAssetPooling、扩展着色器收集、安装或重写 HybridCLR、将 JSON 全套功能并入 Form、改造为复杂依赖注入容器。

## 二、执行原则

- 每批执行“复现或特征测试 -> 修改 -> 回归 -> 记录”，不把全部模块一次性重写。
- 保留用户现有修改，不自动创建新分支，不做覆盖式同步。本计划不包含提交或推送操作。
- 不新增运行时反射。框架日志使用 PLogger；编辑器日志不受运行时 logLevel 限制，删除无价值的新增日志。
- 优先修实现，不为整理命名大规模改 API。确需改变公开行为时，同批更新调用点、文档和测试，不长期保留两套平行入口。
- 测试以正式 EditMode/PlayMode 测试程序集保存，与发布 Player 隔离；桩用于控制延迟、失败和取消，真实 YooAsset/Unity 集成测试用于验证适配契约，不能用桩测试代替平台验收。
- 任何线上上传、覆盖 CDN 指针、删除云端资源均不属于默认修复步骤。集成测试优先使用本地服务或独立测试目录。

### S0：基线与可重复测试

- 重新检查两个仓库的未提交修改、模块版本及源码差异。审查中的 35 份差异是当时快照，不直接当成当前状态。
- 对比源仓库独有内容和验证工程新增内容，记录保留与同步方向。先保持验证工程当前安装结构，不同时迁移 Assets 与 UPM 布局。
- 建立独立测试程序集，保存已复现的调度器用例；记录当前编译、启动与性能基线。
- 临时以经过对照确认的验证工程代码作为修复工作副本，每个通过验收的批次经差异检查同步到独立仓库。最终独立仓库作为发布源；不允许两处无记录地独立修改。

验收：现有功能的基线有记录；失败测试能稳定复现；测试不会进入 Player；同步清单不含凭据、平台构建产物或项目专属配置。

### S1：异步调度与基础生命周期

主要位置：PulletAsyncOperation、PulletOperationSystem、PulletFrameworks 及驱动器。

- 修复完成回调清理调度集合后的索引失效。
- 完成监听者逐项隔离；某个回调或 Abort 逻辑失败，其他操作仍能被清理。异常用 PLogger 保留必要上下文，不能只吞掉。
- 明确终态只产生一次、订阅与通知规则，以及清理期间提交新操作的行为。
- 补充重复 Destroy、部分初始化失败、关闭 Domain Reload 后反复启动退出的收尾保护，不仅依赖 Demo 的 OnDestroy。

验收：完成回调中 Clear/Destroy、监听者抛异常、清理时产生新请求、重复清理均不破坏后续调度；被清理操作全部结束；关闭 Domain Reload 后连续运行退出至少 10 次无残留驱动或重复初始化异常。

### S2：YooAsset 收尾与资源边界

主要位置：PulletYooAssets、PackagePipeline、PackageOperation、YooAssetResourceAdapter、PulletResources、Demo/GameLaunch。

- 将包终态、操作占用解除与业务通知顺序固定下来；同包完成回调允许启动下一步操作。
- 为活动操作增加身份/代次校验，旧操作不能移除新操作或写回新会话状态。
- Reset 在停止协程驱动前确保所有上层句柄进入取消终态；底层暂时不能取消的工作不再影响新会话。
- 统一资源适配句柄的释放、失效、完成回调和异常约定；不把基础异步操作与 YooAsset 操作强行合并成一个巨大基类。
- 明确安装适配器的启动职责；重复安装相同实例可安全处理，替换已安装后端需经过显式卸载流程，不能静默覆盖。
- 将 Demo 中由业务自行持有的飞机、敌机等资源加载改为原生 YooAsset 句柄；保留 UI、Sound、Form、Pooling 内部资源适配路径。
- 在 Demo 中落实退出业务、释放业务及框架使用者、卸载资源包的顺序；不增加框架对 Demo 的引用。

验收：同包 Initialize/Check/Update 连续回调可用；不同包独立运行；在初始化、查版本、清单、下载、预热阶段 Reset 都结束等待；迟到回调无污染；释放重复调用安全；适配器与业务访问的是同一底层包。

### S3：平台路径、版本和发布

- 共用一份资源平台标识规则，修复 iOS 和桌面平台上传/下载目录不同的问题；桌面平台不能不加区分地全部落入 PC。保留现有 WebGL 和 Android 路径。
- 先盘点已有平台目录和自定义 URL 模板，再决定受影响的旧路径迁移说明；不自动移动或覆盖云端对象。
- 统一所有包更新入口的版本选择规则：默认自动流程不选择已知较旧版本，主动回滚需显式表达；无法比较时不猜测大小，返回明确结果。首次无本地版本与已有有效版本的处理分别定义。
- 比较基准包含当前有效版本和可用内置版本；允许显式回滚不代表清单或资源加载失败也应视为成功。
- YooAsset 发布改为调用通用 AssetPublishing 服务，不再直接绑定腾讯 COS；首包和 AB 发布复用上传基础设施，但不混用各自目录或清单规则。
- 固定每次发布的供应商配置、目录、包和版本快照；增加同目标并发发布防护。保持资源文件先传、清单随后、版本指针最后。
- 上传失败不前移版本指针，不把部分成功显示为完成；保留可诊断文件、阶段和原因，不输出密钥。

验收：WebGL、Android、iOS、支持的桌面目标上传/下载 URL 一致；默认包与附加包覆盖新/同/旧/不可比较版本；有无内置资源、首次安装、缓存启动、断网分别测试；中途失败或修改编辑器配置不会产生混合发布。

### S4：UI、Sound、平台、Form 与 Pooling 正确性

按以下小批次分别修改和验收，不以一次“大模块重构”交付。

| 批次 | 修改内容 | 验收重点 |
| --- | --- | --- |
| S4.1 UI / F05 | 每次打开的独立身份；关闭、替换、销毁结束对应操作 | 入场中返回、切根、销毁、缓存重开；旧操作不能因新打开而成功 |
| S4.2 Sound / F06 | 原生 AudioClip 与地址播放统一请求顺序；定义通道暂停、全局暂停、应用暂停及 Stop | A 延迟加载后播放 B 不被覆盖；加载中暂停不出声；手动暂停不被前台恢复误解除；持久化不回归 |
| S4.3 MiniGame / F07 | 初始化及成功后的存储、偏好绑定走统一入口；重试与迟到结果隔离 | 首次失败后成功、取消后重试、重复初始化、关闭后迟到成功；无重复绑定 |
| S4.4 Form | 区分批量读取结束与全部成功，提供失败明细和可控重试 | 文件缺失、解析异常、失败后成功、销毁时仍在读取；继续支持业务 Parse 扩展 |
| S4.5 Pooling | Spawner 销毁终态、实例/资源所有权、归还与销毁竞态、复位约定 | 重复归还、旧句柄使用、外部 Destroy、加载中销毁、失败重试、退出时卸载包 |

音频的平台后端与 Unity 后端保留各自适配，不能把小游戏 API 放入通用 Sound。对象池具体业务状态由业务复位，不假设框架能自动重置任意组件。

### S5：Pooling 性能优化

先测量，再分别修改，避免把“调用层数少”当成性能验收。

- 记录池查找、Spawn/Restore、调度和活跃实例扫描的 Profiler 基线；分开测缓存命中、缓存不足、冷加载。
- 将按资源地址查找池的热路径改为字典索引，保留有需要的遍历结构，并测试两者一致性。
- 为已完成的缓存实例评估即时完成路径，减少不必要的异步调度；明确回调时序，覆盖回调中立即归还/销毁/再次 Spawn。
- 分析 SpawnHandle、回调和参数数组的分配。不能直接循环复用对外可持有的 SpawnHandle，否则旧引用可能操作新租用实例。优先优化内部临时数据；若需要租约/代次方案，先证明必要性和正确性。
- 根据测量结果决定是否降低外部销毁检测的扫描频率或分摊到多帧，并规定检测延迟；不未经测量删除兜底检查。
- `maxCapacity` 的当前含义与总实例上限分清，不静默改变已有行为。

验收：固定设备、同一构建配置下比较优化前后 CPU 和 GC；测试 100、1000、5000 级别生成/归还批次及不同活跃实例规模。大规模案例用于观察退化，不代表承诺所有手机都能维持指定帧率。反复测试后资源句柄/实例数量可回到预期值；所有 S4.5 用例继续通过。

本阶段不承诺绝对零分配，不通过不安全地复用公开句柄换取数字改善。记录实际收益；无收益的复杂优化不合入。

### S6：独立复用、同步和验收

- 复核两个仓库相关模块内容及 .meta/GUID，确认没有同步项目私有配置或构建产物。
- 验证核心框架在不安装 YooAsset、小游戏 SDK 时可编译；用测试资源适配器覆盖框架服务，不额外开发完整的新 AB 产品。
- 验证核心 + YooAsset、以及叠加小游戏模块的依赖组合；发布工具保持 Editor-only。
- 验证工程先使用当前安装布局完成回归。是否转成本地 UPM 是单独的安装布局决策，不和故障修复混在一起；转之前检查样例、SDK 导入和路径引用。
- 至少实际构建验证一个普通 Player，优先 Windows；iOS 等缺少构建环境的项目明确标为路径/静态测试通过而非打包通过。
- 抖音、微信分别走开发者工具流程，再由真机验收确认音频、存储、安全区、前后台及缓存行为。
- 更新 DevelopmentStatus、模块 README、问题关闭记录，分别标记实现完成、自动化通过、开发者工具通过、真机通过。

验收：失败用例不再重现；原有首页、进入游戏、暂停、返回、重新开始可用；首包 Package/CDN、内置 AB 开关、远端更新不回归；必要平台未验收的项目继续保留“待验证”，不笼统宣布全部稳定。

## 四、协作与交付

- 代码、自动化测试、差异检查、文档和本机具备环境的构建可由代理执行。
- 涉及登录、设备声音/触控体验、真机权限和生产后台变更时，再请求用户配合；不能用模拟器结果替代这些确认。
- 每批结束报告修改文件、测试结果、剩余风险，并更新本计划对应状态，不提前勾选完成。
- 当前下一阶段是 **S3/S6 平台验收与真机性能采样**；自动化组合安装与普通 Player 构建已完成，不把开发者工具结果误记为真机通过。

### 2026-09-15：S3（阶段实施，尚未验收全部场景）

- YooAsset 上传与下载使用同一平台目录映射：WebGL、Android、IPhone、Windows、macOS、Linux。旧的 iOS 上传目录 `iOS`、Windows 上传目录 `StandaloneWindows64` 和运行时 `PC` 不自动迁移；旧客户端仍使用旧目录，新版本需要按新目录上传。
- 自动更新会比较当前有效清单与可用内置版本，远端旧版不倒退，数字分段不可比较时明确失败；显式指定 `targetVersion` 才表示有意选择旧版。
- 下载失败时，内置降级必须不低于当前活动清单；不能安全降级时报告错误而非静默切回旧版。
- YooAsset 发布改用通用 AssetPublishing 会话，冻结供应商与配置，按供应商串行发布；资源、清单、版本指针仍按顺序上传。上传前校验报告文件的内容哈希、包版本和目录，上传结果 URL 不一致立即停止。
- 验证项目的小游戏首包上传也使用同一发布会话；该发布器已在 S6 同步至独立仓库。
- 同一清单版本不能直接跳过资源准备：Prepare/Download 在复用活动清单时仍会继续走可选下载与预热，避免上次下载中断后重试误报成功。
